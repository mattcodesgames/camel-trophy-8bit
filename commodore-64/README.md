# Camel Trophy (C64) in WebAssembly

This project runs the Commodore 64 game *Camel Trophy* (`CamelTrophy.d64`, CFB crack, 1985 Tequila) in the browser. It uses a small C64 emulator written in C and compiled to WebAssembly.

## Play

- **Easiest:** double-click `CamelTrophy.html`. It's a single self-contained file with the emulator and disk image built in, so it doesn't need a server.
- **From the `web/` folder** (separate `c64.wasm` and `camel.d64`), start a local server and open http://localhost:8064:

```bash
python3 -m http.server 8064 --directory web
```

### Controls

| Action | Keys |
|---|---|
| Joystick (port 2) | Arrow keys, plus **Space** for fire. Gamepads also work. On touch screens an on-screen pad appears. |
| C64 keyboard | Mapped by key position: Enter = RETURN, Esc = RUN/STOP, F1–F7, PgDn = RESTORE |
| Save / load / reset | F9 / F10 / F12, or use the toolbar buttons |
| Fast-forward | Toolbar toggle. Useful during the game's long decrunch pauses. |

How to play: press fire to skip the intro and again to start. In stage 1, drop the crate from the plane and steer its parachute onto the black target with the joystick. In stage 2, drive the Land Rover.

## Title screen

The CFB-Soft cracker intro has been replaced with a new title and credits screen (`tools/mkintro.py`, written in 6502 assembly and built with the small assembler in `tools/asm6502.py`). It shows a bobbing pixel-art Camel Trophy badge, the credits, a short SID tune and raster bars.

The badge is a 192×84 pixel grid in `assets/logo.txt`, which you can hand-edit. It was generated from the reference logo by `tools/logo_from_image.py`. The intro shows it at full C64 resolution by reusing 8 sprites for 4 rows (32 sprite images): two screen buffers are flipped at each row boundary, and the FLD trick keeps text-row DMA out of the logo area so the flips land on exactly the right raster line.

The original disk image is kept untouched in `assets/CamelTrophy-original.d64`. The build writes `web/camel.d64` with two changes to the original program: the BASIC `SYS` now points to the new intro at $C000, and the depacker's jump into the CFB intro now goes to a routine that moves the game into place and runs it. That routine does the same job as the CFB intro's own exit code. The game's data isn't altered.

The version with the original CFB intro is tagged `original-intro`; `git checkout original-intro` brings it back.

## How it works

`src/c64.c` is a compact PAL C64 emulator:

- **6510 CPU**: all documented opcodes plus the stable undocumented ones, NMOS decimal mode, and the dummy write on read-modify-write instructions (needed for IRQ acknowledgement).
- **VIC-II**: a line-based renderer that supports all text and bitmap modes, sprites (multicolour, expansion, priority, collisions), raster IRQs, badline cycle stealing and the border flip-flops.
- **CIA ×2**: timers, interrupt control, the TOD clock, the keyboard matrix, joysticks and VIC bank switching.
- **SID**: 3 voices with ADSR, sync and ring modulation, and a state-variable filter. Output goes through an AudioWorklet.
- **No Commodore ROMs.** A small replacement KERNAL contains the real IRQ/NMI entry code. Calls to the KERNAL jump table, BASIC `RND` and a tiny BASIC "RUN" (for `SYS` launchers) are trapped and handled in C. The character set is an original font, generated by `tools/mkfont.py`.

## Build

You need the zig toolchain (it bundles clang and `wasm-ld`). It's installed in a local virtualenv:

```bash
python3 -m venv .venv && .venv/bin/pip install ziglang
```

Then build:

```bash
./build.sh
```

`build.sh` regenerates the font, compiles `web/c64.wasm` and writes the self-contained `CamelTrophy.html`.

`tools/native.c` is a headless native harness used for testing. It runs frames with scripted input, takes screenshots (PPM files, which `tools/ppm2png.py` converts to PNG) and dumps RAM:

```bash
clang -O2 -o native tools/native.c && ./native web/camel.d64 1200 "input=320:k60=1;323:k60=0" shots=1000 out=.
```
